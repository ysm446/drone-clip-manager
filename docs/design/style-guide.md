# UI スタイルガイド

作成日時: 2026-08-11 18:34
更新日時: 2026-08-15 03:00

drone-clip-manager の UI を一貫したアートスタイルに保つためのルール。
**UI（見た目・レイアウト・配色・部品）を変更するときは、必ずこのドキュメントに従う。**
ここに書かれていない見た目を新しく足したくなった場合は、まず「既存の部品で表現できないか」を検討し、
どうしても必要なときは実装と同時にこのドキュメントを更新する。

正本は [src/renderer/src/styles.css](../../src/renderer/src/styles.css) のデザイントークン。
このドキュメントはその意図と使い分けを説明するもので、数値を増やすときは必ず CSS 側のトークンから引く。

---

## 0. 基本原則（迷ったらここに戻る）

1. **道具であって作品ではない。** 映像編集の作業画面なので、UI 自身は目立たない。
   主役は動画・サムネイル・タイムラインで、UI はその背景に沈む。
2. **色で主張しない。** 情報の区別は基本「面の明度差 + 太字 + 余白」で行う。
   彩度のある色は **アクセント紫 1 色** と、状態色（ok / warn / danger）だけ。
3. **フラット。** グラデーション、内側光沢、装飾的な影は使わない。
   影は「浮いている面（モーダル・ポップアップ・ノード）」の 2 種類だけ。
4. **情報密度は高め。** 12〜13px 中心のコンパクトな UI。行間や余白を無闇に広げない。
5. **同じ意味には同じ見た目。** 選択・ホバー・無効・危険は、画面が違っても同じ表現を使う。
6. **既存トークンで表現する。** 生の色コードやマジックナンバーを新しく増やさない。

参照している設計思想: VS Code / Obsidian（常時ダークな上下バー、ニュートラルな選択表現）、
DaVinci Resolve（タイムラインの再生ヘッドと区間バー）。

## 1. カラー

### 1.1 トークン一覧

色は必ず CSS 変数で参照する。`:root` がライト、`[data-theme='dark']` がダーク。
現在の既定は `src/renderer/index.html` の `data-theme="dark"`（ダーク固定）。
ライトのトークンも揃っているので、**片方だけ成立する色指定はしない**。

#### テーマ連動（本体）

| トークン | 役割 | light | dark |
|---|---|---|---|
| `--bg` | 周辺クローム（サイドバー、キャンバス、トラック背面） | `#f2f3f5` | `#191919` |
| `--surface` | コンテンツ面（エディタ、カード、モーダル、ツールバー） | `#ffffff` | `#1e1e1e` |
| `--text` | 本文 | `#222222` | `#dadada` |
| `--muted` | 補助テキスト（ラベル、メタ情報） | `#5c5c5c` | `#999999` |
| `--faint` | さらに弱いテキスト（目盛り、空状態、時刻） | `#9e9e9e` | `#666666` |
| `--border` | 境界線・区切り | `#dcdde0` | `#333333` |
| `--hover` | ホバーの面 | `rgba(0,0,0,.06)` | `rgba(255,255,255,.055)` |
| `--selected` | 選択の面（ニュートラル寄り） | 紫 11% | 白 9% |
| `--accent` / `--primary` | アクセント紫（唯一の主張色） | `#6c5cd8` | `#7f6df2` |
| `--accent-text` | アクセント面上の文字 | `#ffffff` | `#ffffff` |
| `--accent-border` | アクセントの弱い枠・グロー | `#b5aaf0` | 紫 50% |
| `--playhead` / `--playhead-text` | 再生ヘッド（シルバー） | `#8a9099` / `#fff` | `#d5d9de` / `#08121a` |
| `--ok` / `--warn` / `--danger` | 状態色 | `#1a7f37` / `#b58a00` / `#d1242f` | `#44cf6e` / `#e0ac00` / `#fb464c` |
| `--danger-bg` | 危険操作のホバー面 | `#ffebe9` | 赤 14% |
| `--overlay` | 背景を覆う暗幕 | 黒 45% | 黒 55% |
| `--shadow-1` / `--shadow-2` | 影（浮きの弱 / 強） | — | — |
| `--scrollbar-thumb(-hover)` | スクロールバー | — | — |

#### テーマ非依存（常時ダークなバー）

上下バー・プレイヤー周りは**テーマに関係なく常時ダーク**（VS Code / Obsidian 方式）。
映像に隣接する UI を暗く保ち、映像の明るさを正しく判断できるようにするため。

| トークン | 役割 |
|---|---|
| `--bar-bg` `#161616` | バーの地 |
| `--bar-surface` `#262626` | バー内のボタン・タブの面 |
| `--bar-hover` `#363636` | バー内のホバー / アクティブ |
| `--bar-border` `#333333` | バーの境界 |
| `--bar-text` `#dadada` / `--bar-muted` `#999` / `--bar-faint` `#666` | バー内テキスト 3 階調 |
| `--bar-danger` `#fb7a7e` / `--bar-ok` `#44cf6e` | バー内の状態色 |

映像の入る面（`.player-pane`、`.clip-thumb`、`.filmstrip-cell`、`.seq-node-thumb`）だけは
テーマに関係なく **`#000` 固定**。映像の周囲に色を置かない。

### 1.2 使い分けのルール

- **面の階層は 2 段だけ**: `--bg`（周辺）と `--surface`（コンテンツ）。3 段目を作らない。
  さらに区別が要るときは面ではなく `1px solid var(--border)` の線で分ける。
- **テキストは 3 階調**: `--text`（読ませる）→ `--muted`（補助）→ `--faint`（あってもなくてもよい）。
  4 段目（`opacity` での微調整）を増やさない。
- **アクセント紫を使ってよいのは以下だけ**:
  - primary ボタンの面
  - フォーカス / 編集中の入力枠
  - 再生位置以外の「いま作っている対象」の枠（`.tl-pending`、`.seq-node.selected`、
    `.clip-card.open`、`.mtl-clip.selected`）
  - シークバーの再生済み塗り、進捗バーの塗り
  - ノードグラフのエッジ・ポート
  - トグル ON のアイコン色（`.tl-mode.on`、`.bgm-controls button.on`、`.mpv-loop.on`）
  - topbar のビュー切替タブのアクティブ面（`.view-tab.active`）
- **コンテンツの選択にアクセント色の面を使わない。** 選択は `--selected` + `font-weight: 600`。
  複数選択など「別軸の選択」は `box-shadow: inset 2px 0 0 var(--accent)` の左バーで足す。
  例外は「いまどの画面にいるか」を示すビュー切替タブだけ（下記 5.10）。
  これは一覧の中の 1 件を選ぶ操作ではなく、アプリ全体の現在地表示なので、面ではっきり示す。
- **危険操作**は通常時は `--faint` / `--text` のまま、**ホバーで初めて** `--danger-bg` + `--danger` に変わる。
  常時赤いボタンを置かない。
- **再生ヘッドはシルバー（`--playhead`）**で、アクセント紫とは別系統。
  「いま再生している位置」と「いま編集している対象」を色で区別するため、この 2 色を混ぜない。

### 1.3 区間（クリップ）の色

区間バーの色は [src/renderer/src/util.ts](../../src/renderer/src/util.ts) の `SEGMENT_COLORS` を
インデックスで循環させる。青系・紫系の明るい 6 色で、隣接する区間が明度差で分かれるよう並べてある。

```
#4f9dff  #a98bfa  #86b6ff  #8f7ff5  #c9b1ff  #6d8df7
```

- バー上のラベルは濃色文字（`#0d0f12`）で置くため、**この配列に暗い色を追加しない**。
- 赤・黄・緑は状態色として予約済みなので、区間色に混ぜない。

## 2. タイポグラフィ

```
font-family: 'Segoe UI', 'Hiragino Kaku Gothic ProN', 'Yu Gothic UI', sans-serif;
```

システムフォントのみ。Web フォントは読み込まない（オフライン前提のローカルアプリのため）。

### 2.1 サイズトークン

| トークン | px | 用途 |
|---|---|---|
| `--fs-xs` | 11 | バッジ、タグ、時刻、目盛り、ステータスバー、セクション見出し |
| `--fs-sm` | 12 | 補助テキスト、バー内ボタン、カードのメタ情報 |
| `--fs-ui` | 13 | **既定**。本文・ボタン・入力・リスト行 |
| `--fs-md` | 14 | モーダルのタイトル |

- 10px はタイムラインの目盛りラベル・再生ヘッドの時刻表示にのみ使う（他に増やさない）。
- **15px 以上の文字を UI に置かない。** 見出しで階層を作るのではなく、余白と区切り線で作る。

### 2.2 ウェイト

- 通常: 400
- 強調（選択行、カードのタイトル、タブのアクティブ、primary ボタン、モーダル見出し）: 600
- **長さ（duration）の数値**: 700 — 編集作業の主役なので唯一 700 を使ってよい箇所
  （`.seg-dur`、`.clip-dur-main`、`.seq-node-dur`）

### 2.3 数値表記

時刻・長さ・パーセント・カウントなど**桁が変動する数値には必ず `font-variant-numeric: tabular-nums`** を付ける。
再生中に数字がガタつくのを防ぐ。

### 2.4 大文字見出し

サイドバーのセクション見出し（`.sidebar-head`、`.bgm-head`）のみ、次の組み合わせを使う。
これ以外の場所で `text-transform: uppercase` を使わない。

```css
font-size: var(--fs-xs);
text-transform: uppercase;
letter-spacing: 0.07em;
font-weight: 600;
color: var(--muted);
```

### 2.5 テキスト選択

`body` は `user-select: none`（アプリらしい操作感のため）。
コピーさせたいテキスト（エラーメッセージ、出力パスなど）にだけ `user-select: text` を明示する。

## 3. 余白・サイズ・角丸

### 3.1 スペーシング

**4px グリッド**（2 / 4 / 6 / 8 / 10 / 12 / 14 / 16）。5px・7px・15px のような値を新しく増やさない。
既存の `padding: 5px 8px` などは踏襲してよいが、新規は上記から選ぶ。

| 文脈 | 標準値 |
|---|---|
| 上下バー | `padding: 6px 12px` |
| ツールバー（エディタ / クリップ / シーケンス） | `padding: 8px 16px` |
| モーダルの各行 | `padding: 12px 16px` |
| リスト行 | `padding: 4px 8px`〜`5px 8px` |
| リストのコンテナ | `padding: 4px 8px 8px` |
| カード | `padding: 8px` |
| ステータスバー | `padding: 3px 12px` |
| 要素間の gap | 小 4–6px / 中 8–10px / 大 12px |

**コンテンツ領域の左右パディングは 16px** で統一（ツールバー・タイムライン・グリッド）。
サイドバー内は 8〜14px と狭め。

### 3.2 角丸

| トークン | px | 用途 |
|---|---|---|
| `--radius-s` | 4 | バッジ、小さいアイコンボタン、区間バー、インライン入力 |
| `--radius-m` | 6 | **既定**。ボタン、リスト行、入力、メニュー、枠付きコンテナ |
| `--radius-l` | 10 | カード、モーダル、ノード |
| `999px` / `50%` | — | スクロールバー、進捗バー、丸いつまみ・ポート・バッジ |

タグチップだけ `10px`（ピル形状）を使う。

### 3.3 固定サイズ

新しい部品を作るときは、既存の寸法に合わせる。

| 部品 | サイズ |
|---|---|
| フィルムストリップ | 高さ 52px |
| タイムラインのルーラー | 高さ 22px |
| タイムラインのトラック | 高さ 56px |
| 区間バーの上下インセット | 8px |
| 再生ヘッド | 幅 2px + 12×14px のマーカー |
| クリップカードのサムネイル | 128×72px（16:9） |
| シークバーのホバー用サムネイル | 160×90px（16:9） |
| ノードのサムネイル | 高さ 94px |
| スプリッター | 見た目 1px / 当たり判定 ±3px |
| 接続ポート | 見た目 14px / 当たり判定 +10px |
| スクロールバー | 12px（うち 3px は透明ボーダー） |

サムネイルの比率は **16:9 固定**。それ以外の比率を新設しない。

## 4. 面と境界

- **境界線は必ず `1px solid var(--border)`。** 2px の枠線は「選択・強調」専用。
- パネル同士の区切りは、影ではなく線 1 本。バーは `border-bottom` / `border-top` を持つ。
- **影は 2 種類だけ**:
  - `--shadow-1`: 弱く浮く面（ノードカード）
  - `--shadow-2`: 強く浮く面（モーダル、シークバーのサムネイル）
  - ポップアップ（コンテキストメニュー、タグ候補）は `0 6px 24px rgba(0,0,0,.35)`
- カードやリスト行に影を付けない。区別は面色と境界線で行う。

### z-index の段

上に積むものが増えたら、この段に合わせる。

| 値 | 用途 |
|---|---|
| 2–3 | 要素内の重なり（チェックボックス、バッジ、ポート、ハンドル） |
| 5–6 | 再生ヘッド、選択矩形、スプリッター |
| 60 | シークバーのホバーサムネイル |
| 90 | 全画面プレイヤー |
| 100 | モーダル |
| 150 | コンテキストメニュー、候補ポップアップ |

## 5. 部品ルール

### 5.1 ボタン

**目立たせるのは 1 画面に 1 つ（primary）だけ。** それ以外はすべて ghost。

| 種別 | 見た目 |
|---|---|
| `.btn`（ghost / 既定） | `--surface` の面 + `--border` の枠、`padding: 4px 12px`、`--radius-m` |
| `.btn.primary` | `--primary` の面 + `--accent-text`、`font-weight: 600`、ホバーは `brightness(1.08)` |
| `.btn.small` | `padding: 2px 8px`、`--fs-xs` |
| バー内の `.btn` | `--bar-surface` の面、枠は透明、`padding: 3px 12px`、`--fs-sm`（chip 風） |
| アイコンのみのボタン | 面・枠なし、色は `--muted`、ホバーで `--hover` + `--text` |
| トグル（ON） | `--selected` の面 + `--accent` の文字色 |
| 危険 | 通常は無彩色、ホバーで `--danger-bg` + `--danger` |

無効時は `color: var(--faint)` + `cursor: default`、または `opacity: 0.35–0.5`。
**無効の表現をどちらか一方に統一できない場合、面のある部品は opacity、テキスト主体の部品は色で表す。**

### 5.2 入力

- 通常の入力: `--surface` の面 + `--border` の枠 + `--radius-m`、フォーカスで `border-color: var(--accent)`。
- **インライン編集**（リスト行の名前変更、ラベル編集）は、非フォーカス時は
  面も枠も透明にして地の文と同じに見せ、フォーカスで `--accent` の枠 + `--surface` の面を出す。
- 独自の `outline` を消したときは、必ず `border-color` で代替のフォーカス表現を用意する。
- キーボード操作用のフォーカスリングは `outline: 2px solid var(--accent); outline-offset: 1px`
  （バー内のボタンのみ、暗色面で目立ちすぎるため無効化している）。

### 5.3 リスト行

ツリー・区間リスト・シーケンス一覧・BGM トラックは同じ骨格を使う。

```css
display: flex; align-items: center; gap: 5–8px;
padding: 4px 8px; border-radius: var(--radius-m); cursor: pointer;
white-space: nowrap; overflow: hidden;
```

- ホバー: `background: var(--hover)`
- 選択 / アクティブ: `background: var(--selected)` (+ 主役の行なら `font-weight: 600`)
- 長いテキストは `text-overflow: ellipsis`。全文は `title` 属性で見せる。

### 5.4 カード

クリップカードとノードカードは同じ言語で作る。

- 面 `--surface`、枠 `1px solid var(--border)`、角丸 `--radius-l`
- 選択: `border-color: var(--accent-border)` + `background: var(--selected)`
- **いま開いている / 再生中**: `border-color: var(--accent)` + `box-shadow: 0 0 0 2px var(--accent-border)`
- サムネイル右下の長さバッジは `rgba(0,0,0,.72)` + `#eee` + `--fs-xs` + `--radius-s`（両画面で共通）

### 5.5 バッジ・タグ

- `.badge`: `--hover` の面 + `--muted` + `--fs-xs` + `--radius-s`。情報の付箋であって強調ではない。
  例外は `.badge.proxy`（アクセント面）— 「いま代替再生中」という機能状態を示すため。
- `.tag-chip`: `--selected` の面 + `--border` の枠 + `border-radius: 10px`（ピル）。
- タグの入力欄は `border: 1px dashed var(--border)` で「追加できる場所」を示し、
  フォーカスで実線 + `--accent` に変わる。

### 5.6 モーダル

- 背景は `--overlay` の暗幕（`z-index: 100`）。
- 本体は `--surface` + `--radius-l` + `--shadow-2`、幅は用途ごとに固定（書き出し 580px / 進捗 440px）、
  `max-width: 92vw`、`max-height: 86vh`。
- 構造は **head（見出し + ✕）/ body / foot（左に要約・右にアクション）** の 3 段で固定。
- foot のアクションは右揃え、`gap: 8px`、実行が primary。
- 設定行は `.modal-row`（左に `--muted` の固定幅ラベル 110px、右に入力）で揃える。
  行内のチェックボックスは `.modal-check`（`<label>` でテキストごと囲む）を使い、
  説明テキストは `--text` / `--fs-ui`。チェックボックス自体は `accent-color: var(--accent)`。

### 5.7 ポップアップ（コンテキストメニュー / 候補）

`position: fixed`、`--surface` + `--border` + `--radius-m` + `0 6px 24px rgba(0,0,0,.35)`、
`padding: 4px`、項目は `--radius-s` でホバー時に `--hover`。
**mpv がネイティブの最前面ウィンドウなので、映像に重なる位置に開くポップアップを作らない**
（タグ候補が入力欄の下に開くのはこの制約による）。

### 5.8 空状態

中央寄せ、`color: var(--faint)`、`font-size: var(--fs-sm)`。
イラストやアイコンは置かず、次に何をすればよいかを一文で書く。

### 5.9 通知

トーストは使わず、下部ステータスバー（`.statusbar`）に 1 行で出す。
成功は `--text`、失敗は `--danger`。`--fs-xs`。

### 5.10 ビュー切替タブ（`.view-tabs`）

topbar のライブラリ / クリップ / シーケンスの切替。排他選択（ラジオ）として扱う。

- 容れ物は `--bar-surface` の面 + `--radius-m` + `padding: 2px`。タブ間の `gap` は 2px。
- 非選択: 面なし + `--bar-muted`。ホバーで `--bar-hover` の面 + `--bar-text`。
- **選択中: `--accent` の面 + `--accent-text` + `font-weight: 600`。**
  現在地はアプリ全体の状態なので、ここだけはキーカラーの面で明示する（1.2 の例外）。
- この扱いは「排他的に 1 つだけ選ぶ画面切替」に限る。
  一覧の中の選択（リスト行・カード）には広げない。
- **同じ扱いをシーケンス画面のビュー切替（`.seq-modes` / ノード・音楽）にも使う。**
  同じシーケンスをどの見方で表示しているかという現在地の表示で、topbar のタブと同種のため。
  容れ物の面だけ、バーではなくコンテンツ面の上に置くので `--bg` にする。

### 5.12 音楽タイムライン（`.mtl-*`）

シーケンス画面の「音楽」ビュー。**曲が上・クリップが下**の 2 トラック構成で固定する
（曲に映像を合わせる機能なので、基準になる曲を上に置く。NLE の慣習には合わせない）。

- ルーラー 22px + トラック 56px（§3.3 の既存寸法をそのまま使う）。
- **ルーラー・波形・拍線 / 小節線は canvas に描く。** 小節線が数百本になり DOM では重いため。
  色は `getComputedStyle` で CSS 変数から引き、トークン外の色を canvas に直接書かない。
  波形と拍線は `--border`、小節線は `--muted`、小節番号は `--faint`、曲の終端のみ `--accent`。
- クリップブロックは DOM。色は区間バーと同じ `colorForIndex`（§1.3）で、文字は濃色 `#0d0f12`。
- 尺は `--fs-xs` の 10px + `font-weight: 700`（§2.2 の「長さの数値」に該当）。
- 曲に対する過不足は `--muted`、曲を越えた場合のみ `--warn`。
- **ブロックの枠は 4 状態を内側 2px の枠で描き分ける**（面の色は素材色なので枠で示す）:
  選択 `--accent` / ドラッグ中 `--accent` / 自動縮小 `--warn` / 素材不足 `--danger`。
  選択にアクセントを使うのは §1.2 の「いま作っている対象の枠」に当たるため
  （`.seq-node.selected` と同じ扱い。一覧の行選択には広げない）。
- **サムネイルは幅で自動的に省く。** ブロックが狭いと絵が潰れて役に立たないので、
  表示トグルとは別に最小幅で切る（現状 64px）。同様に尺の秒数は 52px、
  元の長さの併記は 120px を下回ると省く。**設定ではなく幅で段階的に落とすのが原則。**
  サムネイルは文字と重ねず横に並べる（濃色文字が絵の上に乗ると読めなくなるため）。

### 5.11 拍インジケータ（`.bgm-beat-dot`）

BGM の再生位置が拍に乗ったことを示す 6px の丸。点滅する部品はこれ 1 つだけに留める。

- 消灯: `--border` / 拍で点灯: `--muted` / **小節頭だけ `--accent`**
- 変化は `background` の `0.12s ease` のみ。**大きさや位置は変えない**（§7 に従う）。
- 数値（BPM・小節.拍）は `--fs-xs` + `tabular-nums`。詳細（平均ズレ・テンポ変動）は `title` に逃がす。
- 解析結果が信頼できない曲の注意書きは `--warn` の 1 行（`.bgm-beat-warn`）で出す。
  これは通知ではなく素材そのものの性質なので、ステータスバー（§5.9）ではなくその場に置く。

## 6. アイコン

- [src/renderer/src/components/icons.tsx](../../src/renderer/src/components/icons.tsx) の SVG のみを使う。
  **絵文字を UI に使わない**（フォント依存で見た目が揃わないため）。

- 線のアイコンは `stroke()`（`stroke-width: 1.4`、`linecap/linejoin: round`）、
  再生系の塗りは `solid()` を使う。この 2 種類以外の描き方をしない。

## 7. モーション

- トランジションは **0.12s ease** に統一（`background` / `color` / `border-color` / `opacity`）。
- 進捗バーの伸長のみ `0.15s linear`。
- ローディングは 28px のリングスピナー（`0.9s linear infinite`）1 種類。
- **位置・サイズのアニメーションを使わない**（スライドイン、フェードイン、バウンス）。
  ドラッグ操作の即応性が最優先で、遷移演出は作業のノイズになる。

## 8. 操作フィードバック

- カーソルは意味に合わせる: `pointer`（クリック）/ `grab`→`grabbing`（移動）/
  `ew-resize`（端の伸縮）/ `col-resize`・`row-resize`（パネル）/ `crosshair`（範囲作成・接続）。
- **細い当たり判定は必ず擬似要素で広げる**（スプリッターは ±3px、接続ポートは +10px）。
  見た目の線は細いまま、掴める範囲だけ広くする。
- ドラッグ＆ドロップの受け先は `box-shadow: inset 0 0 0 1px var(--accent)`（枠 1px）で示す。
- 表示しきれない情報は `title` 属性でフォールバックする（区間の長さ、フルパスなど）。

## 9. レイアウト

```
┌ topbar（常時ダーク）
├ body ─ sidebar（--bg / ツリー + BGM）│ splitter │ main
│                                       ├ player-pane（#000）
│                                       ├ splitter
│                                       └ editor-pane（--surface）
└ statusbar
```

**シーケンスモードだけ別レイアウト**（2026-08-15）。上段に素材と映像、下段に組み立て面を置く
（DaVinci Resolve の Edit ページと同じ考え方）。

```
┌ topbar
├ BGM │ クリップパネル │ 再生画面          ← 上段
│     ├───────────────┼──────────────────
│     │ シーケンス一覧 │ ノード / 音楽     ← 下段
└ statusbar
```

- 素材ツリーはシーケンス編集で使わないので隠し、**BGM だけを残して折りたためる**ようにする
  （畳んでも見出しボタンは残り、いつでも開ける）。空いた幅はノード / 音楽タイムラインへ回す。
- **再生画面とクリップパネルを DOM 上で移動させない。** 移動すると再マウントされ、再生位置と
  BGM が飛ぶ。JSX の並びは変えず、**`.main.view-sequence` の CSS グリッドと
  `.sequence-view { display: contents }`** で配置だけを組み替える
  （`display: contents` で各列を親グリッドの項目に昇格させる）。
- そのため**列の幅とスプリッタは親（App）が持つ**。グリッドの定義が `.main` にあり、
  境界は親にしか置けないため。左列の境界は上下 2 段を貫く 1 本にし、
  クリップパネルとシーケンス一覧の左端を揃える。
- ライブラリモードは従来のレイアウト（ツリー + 再生画面 + タイムライン）のまま。

- 全体は縦 flex。スクロールする領域には必ず `min-height: 0` / `min-width: 0` を付ける。
- パネル幅・高さは **inline style + state** で持ち、`Splitter` でリサイズする（CSS に固定値を書かない）。
- 画面切り替え（ライブラリ / クリップ / シーケンス）は topbar のタブ（`.view-tabs`）で行う。
- グリッドは `repeat(auto-fill, minmax(N, 1fr))`（クリップ 320px / パレット 132px）。

## 10. CSS の書き方

- スタイルは [styles.css](../../src/renderer/src/styles.css) の 1 ファイルに集約する。
  CSS-in-JS、CSS Modules、Tailwind を導入しない。
- クラス名は **ケバブケース + 機能ごとの接頭辞**。既存の接頭辞に合わせる:
  `tree-` / `bgm-` / `player-` / `mpv-` / `tl-`（タイムライン）/ `seg-`（区間）/
  `clip-` / `clips-` / `seq-`（シーケンス）/ `mtl-`（音楽タイムライン）/ `modal-` / `tag-` / `status-`
- 状態は独立したクラスで表す: `.selected` `.active` `.on` `.open` `.disabled` `.danger` `.ok` `.err`。
  意味が同じなら同じ名前を使い回す。
- **`--bgm-*` と `--tl-*` / `player-*` のスタイルを共通化しない。**
  BGM は音声、タイムライン・シークバーは映像で、別系統のデザインとして扱う
  （音量スライダーはネイティブ `input[type=range]`、動画シークは自前実装、という差もこの方針による）。
- 追加するセクションは既存の `/* ==== 見出し ==== */` の並びに合わせ、関連する場所に置く。
- 非自明な指定（当たり判定の拡張、重なり順、mpv 由来の制約）には理由を日本語コメントで残す。

## 11. アンチパターン

- ❌ アクセント紫以外の彩色を UI 部品に足す（区間色と状態色は例外）
- ❌ 選択状態をアクセント色のベタ塗りで表す
- ❌ グラデーション・光沢・装飾的なドロップシャドウ
- ❌ 15px 以上の文字、`font-weight: 700` の乱用（長さ表示以外）
- ❌ 面の階層を 3 段以上に増やす
- ❌ 角丸・余白・トランジション時間をトークン外の値で指定する
- ❌ 絵文字アイコン、外部アイコンフォント、Web フォント
- ❌ スライドイン等の登場アニメーション
- ❌ トースト・ダイアログの多用（通知はステータスバー 1 行）
- ❌ ライト/ダークどちらか一方でしか成立しない色指定

## 12. UI 変更時のチェックリスト

1. 追加する見た目は、既存の部品（§5）で表現できないか確認したか
2. 色・サイズ・余白・角丸をすべて CSS 変数 / 4px グリッドから引いたか
3. ホバー / 選択 / 無効 / 危険 の 4 状態を既存ルールどおりに定義したか
4. 数値表示に `tabular-nums` を付けたか
5. ライト・ダーク両方のトークンで破綻しないか（`--bar-*` を使うべき場所ではないか）
6. 映像に重なる位置に要素を置いていないか（mpv 制約）
7. スクロール領域に `min-height: 0` / `min-width: 0` を付けたか
8. 新しい規則を足した場合、このドキュメントを更新し、更新日時を書き換えたか
9. `npm run build` が通るか
